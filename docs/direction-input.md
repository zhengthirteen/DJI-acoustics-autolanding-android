# 方向输入约定

当前没有 TCP、UDP、蓝牙或麦克风采集；本文件规定第一阶段模拟队列的含义，并记录将来接入阵列时必须解决的差异。

## 第一阶段队列

每个采样是一个**从预定降落点指向无人机**的水平地理方位角，单位为度。0° 北、90° 东、180° 南、270° 西，从北顺时针。控制器将其反向，形成指向降落点的速度。

| 输入 | 表示无人机相对目标的位置 | 修正方向 |
| --- | --- | --- |
| `0` | 北侧 | 南 |
| `90` | 东侧 | 西 |
| `180` | 南侧 | 北 |
| `270` / `-90` | 西侧 | 东 |
| `WAIT` | 无有效测量 | 零水平速度 |

队列文本允许逗号、中文逗号、分号、空格或换行分隔；`角度*次数` 表示重复，`WAIT*次数` 表示多个缺测采样。角度归一化到 `[0,360)`；拒绝 NaN、Infinity、空队列、无效重复次数和超过 1200 个采样。

```text
180*40
```

40 个采样，每 500 ms 一个，首个采样在启动后立即产生。它与默认模拟初始位置匹配。另一示例：

```text
180,175,170,165,WAIT,180*20
```

人工构造序列不根据无人机真实运动闭环更新，仅能测试响应。一次队列播放不会因为走到最后就判断到达。角度 0 也不表示对准完成。

## 时间与缺测

控制器只接受未过期、非未来、采样时间严格递增的输入，使用 Android 单调时间 `elapsedRealtime()`；不能将阵列计算机的墙钟毫秒直接传入。方向源以 500 ms 更新，控制器 100 ms 执行一次。

收到 `WAIT` 立即悬停，清除方向滤波，但该采样仍表示方向源在工作。源完全停止更新超过 1.5 秒则停止实验。队列耗尽由 Android 调度器明确停止整个实验。

CSV 的 `monotonic_ms` 是 Android 开机以来的毫秒数，不是 UTC；用同一时基计算控制间隔。

## 阵列接入前必须明确

- 阵列报告“阵列 → 无人机”声源方位、“无人机 → 阵列”方向，还是“目标 → 无人机”偏离方向？
- 零度对齐地理北、阵列某轴还是机头？旋转正方向如何定义？是否包含俯仰角？
- 阵列和降落点是否重合？不重合时如何获得足够信息把阵列方向转换到目标方向？
- 地面端时间戳/序号如何去重、剔除乱序并转换到接收端单调时基？
- 哪个独立信息负责判断到达？声源丢失、置信度低、通信中断如何报告？

示意扩展字段可以包括 `sequence`、`bearing_deg`、`origin`、`frame`、`confidence`，但当前尚未定义或实现网络协议。不能直接把原点不同的阵列测量送入当前队列。
