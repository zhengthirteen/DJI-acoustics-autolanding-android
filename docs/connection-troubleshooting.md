# “遥控器能飞，但 App 显示等待遥测”排查指南（v1.2）

## 这条提示是什么意思

“遥测”是飞机通过 DJI SDK 回传给本 App 的高度、航向、三轴速度、飞行/电机状态、电量等。它不是 GPS 的同义词。现场没有 GPS，也应该能读取这些基础数据。

遥控器能够手动飞行，只能直接证明“遥控器 ↔ 飞机”正常；DJI Fly 能飞/有图传，证明的是 DJI Fly 的连接。当前 App 还需要单独完成 SDK 注册、手机 USB 应用连接、飞控连接和数据读取。如果确实是本 App 执行方向队列后能控制飞机，旧版提示不更新更值得怀疑。

本次代码审查确定：v1.1 空闲状态下的“等待飞行器遥测”文案没有随数据到达更新，可能误报。旧版还将连接失败、字段缺失、数据过期合并显示。是否还存在你这套设备的订阅/推送频率问题，需要看新版逐项诊断，不能只凭遥控器能飞就断定全部正常。

## v1.2 已做的修改

- 显示六项独立检查：SDK 注册、设备连接回调、飞控连接、关键遥测、只读请求回包、控制权。
- 有效的地面遥测显示“通信已建立；飞机在地面，尚不满足启动条件”，不会要求先起飞来验证通信。
- 除了监听推送，还使用 **带回调的异步 `getValue` 硬件读取**补充数据。姿态/高度/速度每 300 ms 尝试读取，其他字段约每秒；每个字段同一时刻只保留一个有效请求，超时后废弃旧请求并重试。
- 不把同步缓存读取当作新数据，不仅靠放宽 750 ms 超时来让界面变绿。硬件回包用请求时间保守计时，晚于 750 ms 的回包丢弃；重订阅前或断连前的迟到回包也不会冒充新遥测。
- 等待 SDK 注册与手机授权完成后再订阅，注册完成/设备重连后自动重建空闲订阅；也可手动“检查/刷新通信”。飞行控制过程中禁止重新初始化订阅。
- 每项显示“缺失/已收到/过期”、更新时间、数据来源和读取错误，支持复制诊断信息。

DJI 官方区分：同步 `getValue(key)` 读取缓存，带回调的 `getValue(key, callback)` 从硬件异步获取；见 [IKeyManager 官方说明](https://developer.dji.com/api-reference-v5/android-api/Components/IKeyManager/IKeyManager.html)。

## 请先在地面这样操作

如果飞机仍在空中，先用遥控器正常落地，再进行换线、退出 App、重新安装等排查。

1. 安装重新编译的 **v1.2 APK（versionCode 3）**；只更新电脑代码不会改变手机上的 App。已有本项目相同 Debug 签名的版本通常可覆盖安装，方法见 [完整手册](operation-manual.md)。
2. 飞机与遥控器正常开机、配对，手机通过遥控器的手机连接线连接。手机能充电不代表 USB 数据通道正常；必要时在地面更换数据线。
3. 完成 DJI Fly 所需的设备检查后退出 DJI Fly，避免两个 App 争用 USB。手机弹出 USB 应用选择时选“声学自主降落”；若一直自动打开其他 App，检查并清除它的 USB 默认打开设置后重连。
4. 打开本 App，让手机联网完成 SDK 注册并授予精确位置权限。这是手机 SDK 权限，与飞机现场有没有 GPS 是两件事。
5. 点击右侧 **“检查/刷新通信”**，不必点击启动，不必起飞。勾选“实机模式”也会自动进行同样的只读检查。
6. 等几秒，查看右侧六项结果。检查过程没有解锁、起飞、移动、降落或申请虚拟摇杆控制权的指令。

## 怎样判断已经可以通信

| 检查项 | 含义 | 正常现象 |
| --- | --- | --- |
| ① SDK 注册 | 应用 Key/包名注册状态 | 已注册；这一步单独成功不能证明飞机已连 |
| ② 设备连接回调 | SDK 是否报告设备连接 | 已连接；仅作为单独证据，不替代飞控参数读取 |
| ③ 飞控连接 | 飞控 Key 的连接状态 | 已连接 |
| ④ 遥测 | 高度、姿态、速度和飞行/电机状态是否齐全、新鲜 | 关键遥测齐全且新鲜；高度、航向、电量等有数值 |
| ⑤ 只读请求 | 本 App 通过 SDK 请求飞机参数后是否收到有效回包 | 已收到硬件参数回包；更新时间周期性刷新 |
| ⑥ 控制权 | 程序有没有接管虚拟摇杆 | 地面检查时应是“未申请控制权” |

当 SDK 已注册、飞控已连接、关键遥测新鲜且收到硬件读取回包时，顶部显示 **“只读通信已确认：硬件参数请求与回包正常”**。这验证了 SDK 参数请求/回传通路，不等于已经验证飞行控制、制动距离或落地效果。

“飞机在地面”“高度低于启动要求”“没有可用定位”等是后续控制启动条件；不能据此说手机没有通信。先通过地面通信检查，再按手册手动起飞、稳定悬停、运行 WAIT 队列。

## 按新版提示定位问题

| 现象 | 下一步 |
| --- | --- |
| SDK 未注册 | 检查联网、权限，以及 [API Key 与包名](api-key-setup.md)；不要用起飞解决注册问题 |
| SDK 已注册，但设备/飞控未连接 | 检查 USB 是否交给本 App、数据线、遥控器配对、飞机开机；遥控器能手动飞不排除手机 App 通道未连 |
| 飞控已连接，全部基础遥测缺失 | 点刷新，查看读取失败原因；检查设备/固件与当前 SDK 的兼容情况 |
| 只有“相对高度”或“三轴速度”等某项缺失 | 查看该行错误，复制诊断；不要把未知值改成 0，也不要关闭保护 |
| 数值有显示，但某行“过期” | 旧数值不能证明仍在收包；看最近更新时间、主动读取是否失败或超时 |
| 遥测正常，但主动硬件读取没有确认 | 推送通路已有数据；主动读可能未返回/不支持，查看具体字段错误，不声称所有读写动作都验证了 |
| 地面通信正常但不能启动控制 | 正常检查起飞、定位、高度、电量、稳定时间；不用先盲目起飞去修复遥测 |
| 停止/控制权交接尚未确认 | 先遥控器接管；停止未确认前不能刷新订阅或重新启动 |

仍有问题时点击 **“复制诊断信息”**，保存复制出的文字，并附上手机型号/Android 版本、遥控器型号、飞机与遥控器固件版本。没有这些逐项数据，目前无法确定你现场剩余的问题究竟是哪一项。诊断不会读取本机 secrets.properties 中的 Key；不需要发送真实 API Key。
