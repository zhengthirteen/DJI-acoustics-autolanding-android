# 安全审查与验证范围

审查日期：2026-10-14；目标版本：1.2。按用户流程和现场反馈审查并修改声学控制器、队列调度、DJI 适配器、Activity 生命周期、起降入口与说明文档。原 DJI Sample/UXSDK 保留为依赖/参考，未对 DJI 二进制飞控实现作安全认证。

## 已修复的主要问题

| 发现 | 修正 |
| --- | --- |
| 人工“确认到达”会在等待后自动降落，与新流程不符 | 移除到达判据及自动降落路径；只有队列结束、稳定悬停且人工单独批准后才申请降落 |
| 队列结束按故障退出，没有持续悬停等待 | 结束转 HOVERING，继续发送零速度，保留运行保护 |
| EMA 在输入反向后短暂沿原方向继续移动 | 队列直接采用当前方向，WAIT 清零；逐方位验证反向修正和机头坐标变换 |
| UI、日志和控制输出共用主线程 | 控制和 SDK 回调移到独立线程；界面心跳过期锁存停止 |
| SDK 遥测回调排队后才取时间会掩盖陈旧数据 | 在收到回调时记录时间，使用该次回调的数值，姿态/高度/速度共同决定新鲜度 |
| 原停止按钮需要在长设置页滚动查找 | 顶部固定红色按钮，确认弹窗也提供紧急制动；不用二次确认 |
| 仅高度上下限，无法发现相对启动高度漂移 | 增加启动高度快照、0.5 m 偏差限制、实际水平/垂直速度限制 |
| 无 GPS 模式可能在完全无定位时继续发送 | 要求可用 GPS 或飞控视觉定位，拒绝 ATTI/未知/其他自动任务模式 |
| 迟到的控制权或降落回调可能越过停止时刻 | 会话撤销、迟到授权释放、迟到降落再次取消；未确认动作阻止新会话 |
| 申请控制权失败可能仍有不确定硬件状态 | 即便 enable 回报失败也发出 disable 请求，不能只凭失败回调认为已释放 |
| 页面重建可能创建新适配器，绕过旧适配器尚未确认的停止 | 增加进程内单一控制会话锁；跨页面紧急制动可转发给旧会话，旧会话未确认前禁止新会话 |
| 非飞行状态可能被误当作完整落地 | 要求非飞行且电机停止；未知/null 状态触发保护，不能视为完成 |
| 声学页面可进入具有其他飞行动作的 DJI 示例菜单 | 改为只读状态面板；旧示例主 Activity 不再对外导出 |

## v1.2 现场反馈修正

- 旧版空闲文案没有随遥测到达更新，已修正；连接、各项数据新鲜度、硬件回包与程序启动条件分别显示。
- 增加异步硬件读取补充订阅，不把缓存或迟到回包当新数据；单个订阅失败不会阻止其他字段或该字段的读取尝试。
- 注册/权限/设备连接就绪后可重建空闲订阅，不在控制中重新初始化。SDK 产品断开回调也触发停止。
- 选择实际方向和时长后编码为原偏离角，防止把“向北”误填成原输入约定的 0°；保留可选文本导入。
- 新增地面通信不发控制指令、常量硬件读取、单字段错误、迟到/跨代次回包、订阅失败补读、断连后旧连接回包，以及方向映射/编辑/导入的回归场景。
- 文案缺陷已从代码确定；用户设备是否还存在 USB 占用、SDK 注册、字段兼容性或时序问题，仍需新版逐项诊断确认。

## 自动检查

1. **纯 JVM 控制场景**：`./scripts/test_acoustics.sh`。覆盖解析与预算限制、最后一项持续时间、长期悬停不降落、显式降落及稳定等待、紧急终止、方向反转、360 个整数方位与多机头变换、遥测/定位/模式/电量/高度/速度异常、过期/未来时间、主循环超时、会话撤销与迟到心跳。
2. **实际适配器主机测试**：在 Gradle 目录执行 `./gradlew :sample:testAcousticBridge`。编译生产用 `DjiFlightBridge.kt`，以确定性 Android/DJI 替身模拟 SDK，覆盖正常悬停与人工降落、主线程停顿、控制线程调度延迟、停止与获取/释放控制权交错、迟到降落和最终确认、取消/释放失败、控制权丢失、未知遥测、定位/模式丢失及页面关闭。没有飞机或通信硬件参与，测试替身不进入 APK。
3. **Android Debug 构建**：在 Gradle 目录执行 `./gradlew :sample:assembleDebug`，检查真实 Android/DJI SDK 的类型与打包；这不运行真实飞控。
4. **本机配置与 Git 检查**：真实 Key 只在忽略的本机文件中，APK、日志、录音和 SDK 路径不提交；检查打包版本、包名和 Key 注入，不在报告中输出真实值。

本次验证：纯 JVM **37 组场景通过**（包含全部 360 个整数方位）；实际适配器主机替身 **27 组场景通过**；Android `:sample:assembleDebug` **编译通过**。测试不发送真实飞行指令；用户已反馈实机测试现象，v1.2 修改尚未在其设备上复测。

## 仍需实机验证的边界

- 没有现场飞机验证，不能保证“绝不乱飞”。尚需验证 SDK 5.17/对应固件的遥测频率、视觉定位字段、BODY 速度轴映射、控制权交接、零速度制动、自动降落及最终确认。
- JVM 与主机替身没有真实风、惯性、地面效应、磁干扰、无线延迟和飞控行为。指令路程上限不等于真实水平范围。
- 软件急停需 App/控制线程/SDK/链路仍能工作，无法保证收回已发给 SDK/飞机的每一条指令。350 ms 为逻辑超时阈值，实际处置受下一次循环、系统调度和无线传输影响，不是硬实时制动承诺。
- 无 GPS 且飞控视觉定位不可用时应拒绝启动/停止；不是通过视觉算法来引导目标，但飞控仍可能依赖自身视觉定位维持稳定。
- DJI 虚拟摇杆文档列出的避障支持机型不含 Mini 4 Pro，本实验不依赖虚拟摇杆避障防撞。参考 [DJI Virtual Stick 文档](https://developer.dji.com/api-reference-v5/android-api/Components/IVirtualStickManager/IVirtualStickManager.html)。
- DJI 自身低电量、返航、失联等保护仍可能动作。软件不关闭这些保护，也没有紧急停转电机接口。
- SDK 停止/释放/取消一直未确认时，界面保持锁定，操作员需遥控器接管；不自动重新夺取控制权。
