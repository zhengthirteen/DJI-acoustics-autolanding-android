# 麦克风阵列到手机的逐步测试手册

版本：2026-11-20。适用 Android App v1.4 与本机独立 VoiceSep 桥接。

本手册验证“阵列 → Mac采集 → VoiceSep测角 → 局域网 → 手机显示角度”。**全程不用连接、起飞或启动无人机。** 通过本手册代表观测链路通过，不代表实时角度已经接入飞控，也不代表达到1°真实定位精度。

## 一 准备好哪些东西

- 已供电并正确连接的阵列与 Orange Pi 板、网线、Mac 的 USB 以太网适配器。
- Android 手机，与 Mac 连接同一可互访的 Wi-Fi；手机 USB 不必连接遥控器。
- 一个持续声源：人声或单个音箱播放宽带声音。先保证环境中只有一个明显声源。
- 做时钟校准时，Mac 扬声器要靠近阵列且不静音；不要让测试音只播放到耳机里。

当前本机配置：

| 项目 | 当前值 |
| --- | --- |
| 阵列地址 | `192.168.3.102` |
| Mac有线服务 | `USB 10/100/1000 LAN`，接口 `en5` |
| Mac有线地址/掩码 | `192.168.3.10` / `255.255.255.0`，网关空 |
| Mac当前Wi-Fi地址 | `172.27.129.194`；换网后以启动脚本输出为准 |
| VoiceSep目录 | `/Users/zheng13/Study/project/VoiceSep` |
| Android/桥接目录 | `/Users/zheng13/Study/project/DJI-acoustics-autolanding-android` |
| 设备登录 | 用户名已配置为root，密码保存在本机忽略配置，不在本文显示 |

原VoiceSep源码保持干净。桥接、启动和Mac兼容代码位于Android项目的 `scripts/voicesep/`。真实凭据只在忽略的 `android-sdk-v5-as/secrets.properties`，文件权限600；不会提交Git或作为手机配置发送。

## 二 每次开始实验只做这一步启动

打开Mac“终端”，复制以下两行：

```bash
cd /Users/zheng13/Study/project/DJI-acoustics-autolanding-android
python3 scripts/voicesep/stack.py start
```

预期：显示三个服务 running，并提示 **“SMD本机凭据已加载”**。已有三个服务时会复用，不会再启动一套；正在采集/操作时保留现有会话，不强行修改凭据。

然后在Mac打开：

- 采集页：<http://127.0.0.1:8012>
- 测角页：<http://127.0.0.1:8011>
- 只读角度页：<http://127.0.0.1:8014>

**密码框留空，用户名保留root，不勾选“在本机加密记住”。** 外置启动器已经通过原系统接口把凭据加载到后台会话。原网页可能仍显示“首次使用请填写密码”，这是原Windows保存逻辑的提示，不表示本机自动加载失败。若浏览器填了以前的旧密码，请清空它，避免覆盖后台已加载值。

如果你绕过启动脚本，单独重启了SMD服务，运行下面一行重新加载即可，无需再输入密码：

```bash
python3 scripts/voicesep/stack.py load-credentials
```

这两条命令只负责启动软件/加载凭据，不会自动校准、播放声音、开始采样或录音。

## 三 测试顺序和通过标准

按 T01 → T08 依次执行。前一阶段未通过，先处理问题，不要靠起飞、关闭校验或伪造valid继续。

### T01 网络和服务检查

操作：

1. 在终端运行 `python3 scripts/voicesep/stack.py status`。
2. 查看三个服务均为running。
3. 运行以下命令：

   ```bash
   networksetup -getinfo 'USB 10/100/1000 LAN'
   ping -c 3 192.168.3.102
   ```

4. 打开采集页和测角页，页面应正常显示。刚启动时“未连接设备”“尚未开始监测”是正常状态。

**通过条件**：有线IP/掩码正确；3次ping均有回复；两个网页可打开；三个服务running。当前本机已验证这些条件，并已通过真实SSH登录及设备身份核对。

注意：SDK还没准备时，6969音频端口可能尚未开启；SSH能连接不等于已开始采样。ping延迟也不代表完整测角链路时延。

不通过：

- 网卡inactive：检查RJ45、网卡和供电。
- 地址169.254开头：有线网卡未处于正确静态网段。
- 网页打不开：检查启动脚本及 `artifacts/voicesep-stack/` 日志，不要结束其他程序抢占端口。

### T02 先做完全不接硬件的软件测试

这是推荐的第一轮，阵列可以不工作，也不需要无人机。程序合成13路带空间方向的音频，再由真实VoiceSep算法算角度。

操作：

1. 在Android项目根目录运行：

   ```bash
   python3 -B scripts/voicesep/audio_demo.py --seconds 120 --angle 45 --hop 256 --step 8
   ```

2. 终端提示预期角度45°、周期128ms后，在Mac打开 <http://127.0.0.1:18014>。
3. 若已安装手机App，也可在只读角度页连接 `http://172.27.129.194:18014`。IP变了就替换为当前Mac的Wi-Fi地址。
4. 等预热完成，观察数值、箭头和序号。此测试直接生成音频数据，不会从扬声器发声。
5. 等120秒结束，查看终端结果。临时测试服务会关闭，正常8011/8012/8014服务保留。

**通过条件**：页面明确标为合成音频；出现有效角度；配置周期128ms；终端最后打印 `PASS`。脚本内部检查有效结果存在、圆周误差中位数不超过8°，并检查输入停止后结果失效。这个门限是软件冒烟测试，不是真实阵列的精度承诺。

**已验证参考**：本机45°/128ms测试得到90个不同有效事件，中位误差0.00°；75°/96ms测试得到621个，中位误差0.11°。这些均是合成数据。

不通过：不要进入真实测试；记录终端错误、运行目录和页面状态。若端口18011或18014被占用，脚本会拒绝启动，不会杀掉占用进程。

### T03 首次进行真实设备采样时钟校准

此步骤会真实启动阵列采样，并通过Mac播放约4秒低幅度测试音。请在现场准备好扬声器位置。

操作：

1. 回到Mac采集页8012。确认用户名root、密码框为空、“在本机加密记住”未勾选。
2. 让Mac扬声器靠近阵列，确认没有静音、没有把音频只输出到耳机。
3. 点击“校准采样时钟”。不要同时打开原厂演示采集或另一套SDK程序。
4. 等待备份、SDK初始化和校准结束。首次可能需要几十秒；看运行记录，不要连续重复点击。
5. 记录页面显示的“实际采样率”和“设备报告采样率”。

**通过条件**：出现“时钟校准完成……现在可以准备设备”；页面有实际采样时钟记录。不能只凭听到测试音、SSH成功或SDK初始化成功判为通过。

当前设备配置报告48kHz；真实采样时钟要由本次校准决定。不要把资料中曾测得的24kHz直接填成校准结果，也不要为了通过而改原设备配置。

不通过：没有听到音，先检查输出设备；提示未检测到测试音，检查距离/音量/环境；提示设备被占用，先正常结束原来的实验，不强制杀服务；提示身份不符，不关闭身份校验。

### T04 准备设备并验证真实音频预览

操作：

1. 校准成功后点击“准备设备”。校准结束会释放设备，所以这一按钮仍需点击。
2. 等页面进入“预览中”。
3. 在阵列附近连续说话，查看前13路的电平/波形及接收帧数。
4. 保持预览约30秒，查看是否出现断流、格式错误或采样速率异常。

**通过条件**：状态为预览中；SSH、驱动、SDK、数据流健康检查正常；接收帧数/字节数持续增加；有声音时实际接入的麦克风电平能响应；30秒内没有连续断流或协议失败。

不是所有18路都必须有明显声音：代码当前向算法使用前13路，其他通道可能未接或是环回。不要把静音通道自动补零或改编号。

不通过：保存运行记录与状态，不进入测角；不能把“SDK已初始化”代替真实音频已收到。

### T05 开始保存供算法读取的音轨

操作：

1. 选择“前13路”。
2. 录音采样率选择 **16 kHz（流式保存）**，不要选设备原始采样率交给DJ_Drone。
3. 填一个新的实验名，例如 `phone-angle-20261120-01`，点击“开始录音”。不要复用已有目录覆盖记录。
4. 点击该实验“复制路径”，保存这个路径。
5. 查看实验目录，应有 `音轨.wav`、`音轨-2.wav` 至 `音轨-13.wav`，录音继续时文件持续增长。

**通过条件**：SMD为“录音中”；保存采样率为16000Hz；13份WAV存在且继续增长；没有写入、截断或磁盘空间错误。

Mac无需使用原网页的Windows“打开文件夹”功能。可复制路径，在Finder“前往文件夹”中粘贴查看。

### T06 在电脑启动实时测角

操作：

1. 打开测角页8011，将T05的实验目录粘贴到“音轨所在目录”。不要选择“配置文件”子目录，也不要选择T02的合成目录。
2. 点击“检查输入”，确认13路格式、16kHz和共同可读样本正常。
3. 选择 **单一主声源**；先不用旋翼筛选，也不用生成分离音频。
4. 点击“开始监测”。保持SMD继续录音。
5. 用持续的人声或宽带声音发声，等待预热完成。时钟校准的单频测试音不适合替代此处的方位实验。

**通过条件**：分析为active，出现valid=true的角度；新事件序号持续增长；原始角在0–360°范围；持续输入期间没有反复stalled/resyncing；常态RTF小于1、文件积压没有持续增长到上限。若不能持续跟上，先关闭分离等额外工作并检查电脑负载。

注意：字段sequence同时计状态/方向事件；HTTP请求次数或WebSocket心跳次数不是测角次数。没有声源或不够可靠时valid=false是正常输出，不要改成固定角度。

### T07 手机接收真实角度

操作：

1. 安装本项目 `sample-debug.apk`，版本v1.4。仍不连接无人机，也不勾实机控制。
2. 点“阵列实时角度（只读，不接无人机也可）”。
3. 填写 **Mac的Wi-Fi地址和网关端口8014**，例如 `http://172.27.129.194:8014`，点击“连接只读角度”。真实数据不使用T02的18014端口。
4. 确认顶部不是合成角度/合成音频演示，Mac的SMD正在录真实阵列。
5. 先把声源固定，比较手机与Mac的角度、run/epoch/sequence及配置周期。

**通过条件**：网关已连接、VoiceSep上游可访问；有有效源时显示角度和箭头；周期与电脑的configured_update_ms一致；同一事件标识的角度一致（只允许显示舍入差异）；无需要DJI注册或飞机起飞的要求。

不同屏幕可能显示不同的最新序号，不能把不同事件的角度差直接当成解析错误。

不通过：手机不能用127.0.0.1，那指向手机自己；也不要填板子的192.168.3.102。检查同网、防火墙、校园网客户端隔离及IP是否变化。复制手机链路诊断，不发送凭据文件。

### T08 方位符号和异常场景

**方位符号检查**：给阵列标出物理+x、+y，声源尽量与阵列近似同高。分别在+x、+y、-x、-y方向持续发声，等角度稳定后观察约3秒。

| 声源位置 | 应靠近的原始角 | 初步符号检查范围 |
| --- | --- | --- |
| +x | 0° | 315°–360°或0°–45° |
| +y | 90° | 45°–135° |
| -x | 180° | 135°–225° |
| -y | 270° | 225°–315° |

**通过条件**：四个方向都能在持续有效输出期间落在正确象限，并且声源逆时针移动时角度按逆时针约定变化；跨359°/0°时箭头连续转动。这个宽范围只检查坐标/符号，没有验收1°精度。精度需另行固定真实方位、导出角度日志并统计圆周误差。

随后测试以下故障，仍不连接无人机：

| 操作 | 应出现的现象 | 通过标准 |
| --- | --- | --- |
| 电脑点击停止监测 | 手机角度/箭头消失，提示停止或过期 | 默认128ms下建议2秒内清除旧角度，不保持有效旧值 |
| 重新开始监测 | 新run/序号，预热后重新显示 | 不把旧run数据当成新结果；恢复的只是显示 |
| 手机断开Wi-Fi或点断开监听 | 角度清除，显示未连接/过期 | 不继续显示有效旧方向；恢复需按只读页连接流程 |
| 停止录音，让文件不再增长 | 电脑/手机最终显示输入停滞或无效 | 不把静止文件当实时音频 |
| 改合法算法周期再启动，例如hop192、step8 | 电脑和手机显示96ms | 手机自动跟随，无需改APK；回到hop256、step8则为128ms |

真实环境“停止说话”后可能还有风扇等背景声被当成主声源，因此不要只用静音来判断通信断流；停止监测或停止写入是明确的断流测试。

## 五 正常结束与下一轮

1. 先在DJ_Drone点停止并封存。
2. 在SMD点停止并保存录音，再点结束实验，等待设备释放。
3. 手机断开监听。下一轮录音用新实验名，并把新目录重新填到DJ_Drone。
4. 当天不再使用时执行：

   ```bash
   python3 scripts/voicesep/stack.py stop
   ```

5. 日志、录音和本机凭据不提交Git。可以把本表复制到本项目忽略的 `experiments/` 目录作为本次记录；原始数据保留在VoiceSep的实验目录。

## 六 常见问题速查

| 问题 | 怎么处理 |
| --- | --- |
| 旧版start报端口占用，status却显示stopped | 已修复中文终端日期格式导致的误判；直接重新运行start即可复用原服务，不需杀进程或删除进程记录 |
| 新版显示listening-unverified | 端口确实有监听，但未通过进程身份校验；按显示的端口/PID检查，脚本不会自动接管或关闭它 |
| 原网页还提示首次填写密码 | 运行stack start/load-credentials确认“已加载”，密码框清空、用户名root，取消Windows加密记住 |
| 提示“请填写阵列SSH密码” | 后台可能单独重启；执行load-credentials。不要把密码填进源码或聊天诊断 |
| 提示“设备操作正在进行” | 等当前校准/准备/结束完成，不并发点击 |
| 预览有声，但DJ_Drone没角度 | 检查是否在录音、13路16kHz、目录是否本次目录、是否选单一主声源、是否有持续声源 |
| 看到固定旧角度 | 检查valid、结果年龄和run/sequence是否更新；停止后仍不清除则判异常处理未通过 |
| 角度正负/方向相反 | 核对实物+x/+y、通道顺序及逆时针约定；不要只凭手机朝向解释原始角 |
| 新实验一直等待输入 | DJ_Drone可能还监视上一条录音目录；停止后选择新目录重新开始 |
| 指标更新频率明显低 | 看RTF/积压和计算负载；手机备用周期不会改变算法频率 |

原系统采样率、坐标、周期及源接口说明见 [Mac联调指南](voicesep-mac-integration.md)；手机安装步骤见 [操作手册](operation-manual.md)。
