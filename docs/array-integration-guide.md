## 2. 两种输入模式

| 模式 | 每项时长 | 数量上限 | 原有数据含义 |
| --- | --- | --- | --- |
| 原有方向队列 | 500 ms | 120 项 / 60 秒 | 原方向选择器、预设、保存的队列均保留 |
| 阵列角度回放 | 100 ms（10 Hz） | 600 项 / 60 秒 | 原始“阵列 → 音源”角度，经过标定后控制 |

每次新打开仍默认原有队列模式、本地模拟，原 `WAIT*20` 仍是 10 秒。阵列模式单独默认 `WAIT*100`，也是 10 秒，不会把旧队列突然加速五倍。

阵列角度滚轮范围 0–359°，步长 1°；文本也支持小数、负数和跨周角度，不会限制成八个方向，也不会把小数粗化成整数。“每格 1°”只是输入分辨率，不保证真实阵列测角误差只有 1°。

## 3. 角度必须先校准

本版本处理**水平面方位角 azimuth**：从阵列看，音源/无人机位于哪个方向。它不是飞机应直接飞向的角度，也不是机头朝向或俯仰角。

需要填两个参数：

1. **阵列 0° 轴的地理朝向**：北 0°、东 90°、南 180°、西 270°。
2. **原始角增大的方向**：顺时针或逆时针。

换算公式（角度制）：

```text
音源地理方位 = normalize(阵列零点地理朝向 + 符号 × 原始角)
符号 = +1（顺时针）或 -1（逆时针）
向阵列修正方位 = normalize(音源地理方位 + 180°)
```

| 零点朝向 | 增大方向 | 原始角 | 音源所在方向 | 修正移动方向 |
| --- | --- | --- | --- | --- |
| 北 0° | 顺时针 | 0° | 北 | 南 |
| 北 0° | 顺时针 | 90° | 东 | 西 |
| 东 90° | 顺时针 | 0° | 东 | 西 |
| 东 90° | 逆时针 | 90° | 北 | 南 |

原始 0° 是正常方位，不能代表到达。原始 359°、0°、1°应对应连续邻近方向。阵列移动/转动后需要停止实验并重新校准。

**只有阵列中心与目标点的水平位置重合时，当前转换才能直接用于朝目标修正。** 如果不重合，只有方位、没有距离，就无法求出无人机相对另一个目标点的方向；需另加位置/距离估计器。界面会要求明确勾选这一条件，否则只可预览转换，不能启动该角度回放。不要为了通过检查而勾选不符合现场的条件。

“已核对角度标定”不自动保存；进入实机模式、切换输入模式、修改零点/旋转方向/目标关系后都需要重新核对。勾选前先用已知的声源位置验证正反方向。

## 4. 今天即可做的手机测试

1. 安装 v1.3。先选“原有方向队列”，按已经成功的操作检查 DJI 通信和原队列；原流程见 [完整手册](operation-manual.md)。
2. 保持“实机模式”关闭，选择“阵列角度回放 · 0.1 秒/项”。
3. 在本地模拟中设零点北 0°、顺时针，并以“目标水平位置与阵列中心重合”作为模拟假设。
4. 清空文本，输入 `0*10,WAIT*40`，或滚轮选择 0°、1 秒并添加，再添加 WAIT 4 秒。速度设 0.1 m/s。
5. 点“预览选中角度的换算”，应显示原始 0° → 音源方位 0° → 修正方位 180°。
6. 点“检查并保存队列”，应是 **50 项 / 5 秒 / 100 ms 每项**。
7. 本地模拟启动后应向南移动约 1 秒、零速度 4 秒，随后一直 HOVERING。理想模拟北坐标约 -0.1 m；不应自动降落。
8. 将零点改为东 90°，同一原始 0°应改为向西修正。核对 359°/0°/1°跨界、逆时针设置、紧急制动、人工降落。

原有“方向队列”的 `0` 与新阵列原始 `0` 不能在未标定时混用；两种模式分别保存，当前模式和输入周期会显示在状态区、启动确认及日志头中。

DJI 控制输出仍由原适配器以约 100 ms 周期发送。Android 不是硬实时系统；10 Hz 回放遇到小幅调度抖动时取当前时间槽，跳过未执行的旧槽，不补发一串历史移动命令。总时长不延长；超过原有 350 ms 控制循环上限仍终止。

## 6. 预留的代码接入点（内部接口，不规定线上格式）

位置：`android-sdk-v5-sample/src/main/java/dji/sampleV5/aircraft/acoustics/core/`。

- `ArrayAngleCalibration`：固定本次会话的零点、正方向和目标原点关系。
- `DirectionQueue.parse(text, 100)`：100 ms 有限回放；默认 `parse(text)` 仍是原来的 500 ms。
- `LiveBearingInput`：线程安全的最新角度缓冲，不包含网络/串口代码。
- `AcousticLandingController(Config, LiveBearingInput)`：实时输入复用现有控制器及 DJI 适配器；原有限队列构造方法保留。

解析器确定之后，在独立的接收适配层调用：

```java
// 必须按现场实际标定填写，不能照抄示例当作已确认的真实参数。
ArrayAngleCalibration frame = new ArrayAngleCalibration(zeroHeading, clockwise, targetAtArray);
LiveBearingInput input = new LiveBearingInput(frame);

// 每次解码成功后调用。null 表示显式无效/低置信度，0.0 表示真实的 0°。
// capturedAtPhoneMs 已转换到手机单调时基；receivedAtPhoneMs 由手机自己在接收时取值。
input.offer(sequence, rawAzimuthDegrees, capturedAtPhoneMs, receivedAtPhoneMs);

// 将它交给原有 bridge.start(controller) 前，继续保留原 SDK/权限/遥测检查，
// 并检查 input.readyForStart(phoneNow)。控制器实际启动时会再次检查输入新鲜度。
AcousticLandingController controller = new AcousticLandingController(
    new AcousticLandingController.Config(0.1), input);

// 链路断开/解析器失去帧边界：终止，不当成正常队列完成。
input.fail("阵列链路断开");

// 只有独立的人工“结束输入并悬停”操作可调用：
input.finishForOperator(phoneNow);
```

控制器在真正开始时清除开始前的方向值，等待新的帧；旧序号/旧时间的迟到包不能开始移动。结束后重新实验需新建输入对象。实际接入时应增加独立的“阵列接收正常/最后有效角度/数据年龄/丢弃数”显示，继续将它与 DJI 通信状态区分。

当前 Android 界面只暴露两个有限回放模式。等链路确定后，新增接收/解析层和实时输入的界面绑定即可；无需重写 `DjiFlightBridge` 的连接、遥测或速度轴映射。

## 7. 实时输入保护与验证边界

- 启动前需要新鲜有效角度；启动后只使用最新帧，不重放网络积压。
- 有效角度年龄达到 200 ms：零速度；达到 500 ms：锁存停止并由原适配器交还控制权。
- 显式无效测量立即零速度；持续无效不能刷新“最后有效测量”的期限。
- 乱序、重复、未来、接收时已超过 200 ms 的角度丢弃；NaN/Infinity 终止。
- 断流后的迟到帧不能自动恢复；输入/控制会话不复用。
- 实时输入最多运行 60 秒；原有累计指令路程、高度、实际速度、电量、遥测、界面心跳和紧急制动保护继续生效。
- 有限回放结束进入 HOVERING；实时传输断线属于故障。只有人工正常结束输入才进入持续悬停，之后仍需人工单独批准降落。
- 原队列的 WAIT 与有限回放中的 WAIT 可用于悬停实验；实时流持续没有有效角度会超时终止。

本次通过原 37 组控制回归、新 18 组阵列输入场景，以及 30 组实际适配器主机替身场景；Android 已编译。新增场景包含所有整数角度、8 个零点朝向、两种旋转方向、100 ms 时序/抖动、过期与乱序、断流、手动结束和降落。测试替身不连接飞机。

原版的实际连接、队列移动与降落已由用户验证；v1.3 新模式、阵列硬件链路、现场标定与真实噪声下的行为尚待实测。先做地面只读数据检查，再做本地回放、短时低速实机验证。最终落区由人工确认，不要让飞机直接落到阵列设备上。
