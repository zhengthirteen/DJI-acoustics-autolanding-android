# 声学方向序列实验：完整新手操作手册

适用版本：1.2，更新于 2026-10-14。面向当前 Mac 上的项目和 Android 手机。请按“电脑准备 → 安装手机 → 本地模拟 → 地面检查 → 手动起飞 → 短序列实飞”的顺序操作。

> 当前流程：先设定方向队列；人工起飞并飞到目标上方；点击启动；无人机按队列保持高度移动；序列结束后悬停；最后人工选择降落或交还遥控器。App 不自动起飞，不自动判断到达，不因队列结束自动降落。

## 1. 先认识几个文件和设备

- **项目/源码**：给电脑编译的文件夹，不能直接复制到手机当 App 用。
- **Android Studio**：电脑上打开、编译、安装 Android 项目的工具。
- **Gradle**：Android Studio 调用的构建工具，负责下载依赖和生成安装包。
- **APK**：Android 手机的安装文件；本次使用已签名的 Debug APK 即可内部测试。
- **API Key**：让 DJI SDK 注册的应用标识，已在这台 Mac 的本机配置中填好。
- **实机模式**：允许启动后控制真实飞机；默认关闭。未勾选时是本地模拟。
- 当前项目面向 **DJI Mini 4 Pro + RC-N2 + 64 位 ARM Android 手机**。手机最低 Android 7.0；实际系统、固件与设备兼容性需现场验证。电脑模拟器通常是 x86，本项目 APK 只有 arm64，建议在真 Android 手机上测试界面。

新项目目录：

```text
/Users/zheng13/Study/project/DJI-acoustics-autolanding-android
```

Android Studio 应打开的目录：

```text
/Users/zheng13/Study/project/DJI-acoustics-autolanding-android/android-sdk-v5-as
```

原毕设目录与这个目录独立。本机配置复用了原 App 包名，因此手机上原视觉 App 和本次 App 不能同时安装在同一个 Android 用户空间；这不影响电脑上的两个源代码目录。

## 2. 安装/检查电脑环境

已有 Android Studio 且本项目已能编译的这台 Mac，可直接从第 3 节开始。换电脑时才需要重新准备环境。

1. 从 [Android Studio 官网](https://developer.android.com/studio) 安装 Android Studio，首次启动按向导安装 Android SDK。
2. 在 Android Studio 的 `Tools → SDK Manager` 中，安装 **Android SDK Platform 35** 和 **Android SDK Platform-Tools**。SDK Tools 中保留/安装本项目构建需要的 Build-Tools；当前 AGP 8.5 使用的默认 Build-Tools 为 34.0.0。
3. 打开 `Settings/Preferences → Build, Execution, Deployment → Build Tools → Gradle`，把 **Gradle JDK** 选为 **JDK 17**。若没有，使用下拉列表的 Download JDK 选择 17，或选择已有 JDK 17 安装路径。
4. 保持联网。首次同步需要下载 Gradle、Kotlin、DJI SDK 等，可能需要几分钟，具体取决于网络。无需另行手动下载 DJI SDK 压缩包。
5. 本项目已使用 Gradle Wrapper；不要自行把 Gradle、AGP、Kotlin、SDK 版本全部升级。先使用仓库给定版本完成编译和测试。

Android Studio 版本不同，菜单文字可能略有差异，可用菜单搜索查找 `SDK Manager`、`Gradle JDK`。

## 3. 正确打开项目

1. 启动 Android Studio，欢迎页面选择 **Open**；已经打开别的项目时用 **File → Open**。
2. 选择上面完整路径中的 **`android-sdk-v5-as`** 文件夹，点击 Open。
3. 如果出现信任项目提示，核对路径是自己的新项目后再信任。
4. 等待 Gradle Sync 完成。底部 Build/Sync 窗口没有红色错误后继续。
5. 如果左侧列表难找文件，把视图从 Android 切换为 Project。应用模块显示为 **sample**，它的源代码目录实际上是同级的 `android-sdk-v5-sample/`，这是本仓库的正常组织方式。
6. 上方运行配置选择 **sample**。若列表没有该配置，先等同步成功，再从 Run → Edit Configurations 新建 Android App 配置，Module 选 sample。

不要把整个原毕设目录作为本次项目打开，也不要只打开 `android-sdk-v5-sample/`。

## 5. 编译并生成 APK

推荐第一次使用以下命令，路径和产物最明确。

1. 在 Android Studio 底部打开 **Terminal**；也可以打开 Mac 的“终端”。
2. 复制执行：

   ```bash
   cd /Users/zheng13/Study/project/DJI-acoustics-autolanding-android/android-sdk-v5-as
   ./gradlew :sample:assembleDebug
   ```

3. 等到终端出现 **`BUILD SUCCESSFUL`**。
4. 生成的安装包位于：

   ```text
   /Users/zheng13/Study/project/DJI-acoustics-autolanding-android/android-sdk-v5-sample/build/outputs/apk/debug/sample-debug.apk
   ```

5. 文件约 190 MiB，包含 DJI 原生库，比较大是正常的。修改代码或 Key 后，必须重新编译并重新安装，手机不会自动读取电脑上的改动。

也可在 Android Studio 的 Build 菜单中选择生成 APK 的操作，常见名称为 `Generate App Bundles or APKs / Build APK(s)`；菜单随版本变化，以 `assembleDebug` 命令为准。

`assembleDebug` 得到的是已经用本机 Debug 签名签好的 APK，可以直接侧载安装。首次联网下载依赖时不要加 `--offline`。参考 [Android 官方构建说明](https://developer.android.com/build/building-cmdline)。

## 6. 安装到 Android 手机

### 方式 A：Android Studio 直接安装（推荐）

1. 手机打开 设置 → 关于手机，连续点击“版本号/Build number”约七次，直到提示开发者模式开启。各品牌入口可能不同。
2. 返回设置，进入“开发者选项”，打开 **USB 调试**。
3. 用能传输数据的 USB 线连接电脑与手机，保持手机解锁。
4. 手机上出现“是否允许 USB 调试”时，核对是自己的电脑后点击允许。
5. Android Studio 上方设备列表应出现你的手机，选择它；运行配置选 **sample**。
6. 点击绿色三角 **Run ▶**，等待编译、安装、启动。此时只是安装和打开 App，不会自动起飞或开始实机控制。
7. 若没有识别设备，换数据线/USB 接口，检查授权，或打开 `Tools → Troubleshoot Device Connections`。Mac 通常无需额外驱动；Windows 可能需要手机厂商的 ADB 驱动。

依据：[Android 官方真机运行指南](https://developer.android.com/studio/run/device)。

### 方式 B：把 APK 复制到手机后安装

1. 使用第 5 节命令生成 `sample-debug.apk`。
2. 通过 USB 文件传输或你常用的文件传输工具，把 APK 复制到手机的 Download/下载目录。
3. 在手机文件管理器中点击该 APK。
4. 若系统要求允许此文件管理器“安装未知应用”，允许后返回安装界面继续。
5. 安装完成后打开“声学自主降落”。

如果 Android Studio 的 Run 产物出现 `INSTALL_FAILED_TEST_ONLY`，请使用第 5 节的 `assembleDebug` 重新生成可手动安装的 APK。

### 遇到“与现有应用冲突/签名不一致”

本机复用的包名是 `com.zheng13.gradproject`。原视觉 App 与当前 APK 的签名可能不同，因此不能直接覆盖安装。

- 需要保留原 App：采用新包名及新 Key，按 [Key 指南](api-key-setup.md) 操作。
- 决定替换原 App：**先备份原 App 的实验数据和日志**，再在手机设置中卸载原 App，然后安装本次 APK。卸载会删除其应用数据。

不用删除电脑上的原毕设目录。仅更改 App 显示名称也不能解决同包名签名冲突。

## 7. 第一次打开：只做本地模拟

此步骤无需飞机起飞，甚至可以不连接遥控器。SDK 注册失败也不影响本地模拟。

1. 确认 **“实机模式”未勾选**。
2. 在预设下拉框选择“仅悬停 10 秒（首次测试）”，点击“使用所选预设”。速度 `0.1`，模拟机头角度 `0`。
3. 点击 **“检查并保存队列”**，应提示 20 项、10 秒。
4. 点击 **“启动本地模拟”**。初始模拟高度为 4 m，状态进入 `RUNNING`，所有水平命令为零。
5. 约 10 秒后进入 **`HOVERING`**。继续等 10 秒，应该仍悬停，不会自动下降。
6. 稳定悬停 2 秒后，**“人工申请降落…”**启用。先点击并选“取消”，应继续悬停。
7. 再次点击，选择“确认”，才会进入模拟降落，最后进入 `COMPLETE`。
8. 新开一次模拟，运行中点击顶部红色 **“紧急制动”**：本次队列终止，不会续播。重新开始必须再次点击启动。

再选择“向北 1 秒 → 悬停 4 秒”预设（内部文本 `180*2,WAIT*8`）验证方向：0.1 m/s 时应先向北运动 1 秒，随后零速度 4 秒，最终持续悬停。模拟 N 坐标约增加 0.1 m。改变模拟机头角度到 90°，地理移动方向仍应向北。

### 自定义队列：选择方向和时长

1. 要重新编排时先点击“清空队列”。
2. 下拉选择实际移动方向：悬停、北、东北、东、东南、南、西南、西、西北。以地理方位为准，不是机头前后。
3. 在时长下拉框选择持续多久，最小 0.5 秒；点击“＋ 添加这一段”。
4. 重复添加其他段。列表中可以“改时长”“上移”“下移”“删除”。
5. 检查总时长与顺序，再点击“检查并保存队列”。总长最多 60 秒，移动指令路程仍限制 3 米。
6. 已有文本可通过“导入文本…”一次粘贴；这个可选入口仍使用偏离角，不是实际移动方位角。

选择“向北”自动编码为偏离角 180；选择“向东”自动编码为 270。队列执行中禁止编辑，结束后先交还遥控器再修改。

## 8. 地面连接与准备

1. 让手机联网，打开 App，等待右侧显示 **`SDK：已注册`**。首次注册必须能访问 DJI 服务。
2. 安装完成后断开手机与电脑的 USB 线，把手机连接到 RC-N2；遥控器与飞机按正常流程开机、配对。飞机保持在地面。
3. USB 选择应用时选“声学自主降落”。避免 DJI Fly 与本 App 同时争用遥控器 USB 连接；先在 DJI Fly 完成必要的激活、固件和设备检查，再按实际设备情况退出并连接本 App。
4. 勾选“实机模式”。如果请求手机精确位置权限，请允许；这是手机 SDK 的权限要求，不等于要求飞机现场有 GPS。
5. 此时 App 只读取遥测，不发送起飞或移动指令。地面上“未飞行”导致不能启动是正常保护。
6. 点击“检查/刷新通信”，依次检查注册、设备连接、飞控连接、关键遥测、硬件回包和控制权。地面上可确认通信，不需要先起飞；详见 [专项排查指南](connection-troubleshooting.md)。有问题可点击“复制诊断信息”。
7. 使用“仅悬停 10 秒”预设，速度 `0.1`，点击“检查并保存队列”。首次实飞不用运动序列。
8. 飞行场地必须能目视飞机、无旁人进入、留有足够缓冲范围。操作员握持遥控器，最好另一人负责手机操作和观察。先确认熟悉飞机的正常手动飞行与接管方法。

当前代码只有在有效 GPS 或飞控报告使用视觉定位时才允许接管。无 GPS 且下视定位不可用时会拒绝启动；不要通过删除保护条件解决这个提示。

## 9. 按你的流程手动起飞，再启动程序

1. App 中先设好队列。**不要点击启动**，先用遥控器按 DJI 官方手册完成手动起飞。
2. 手动把飞机飞到预定目标正上方，确认周围有足够水平余量。程序不会自动飞到目标，也不知道目标距离。
3. 本实验允许相对起飞点高度 **2–8 m**；这个高度是起飞点参考值，不一定等于当前位置离地高度，地面应尽量平整。
4. 放开水平/垂直操纵输入，让摇杆回中并稳定悬停。右侧需要连续至少 2 秒满足：电量≥30%、有效定位、允许的正常飞行模式、水平和垂直速度均不超过 0.2 m/s、遥测新鲜。
5. 看到启动检查允许后，点击 **“已手动定位，启动实机序列…”**。
6. 确认弹窗中的队列时长、速度与场地情况，再点击“确认”。如果此时不合适，点取消。
7. App 申请控制权，确认成功后才开始队列。若获取控制权失败或超过 5 秒，程序终止，按状态提示用遥控器接管。
8. 执行过程中目视飞机，手机保持前台、屏幕不要锁定；避免插拔连接线、切到其他 App 或在空中修改权限。页面离开前台会终止本次实验。
9. `WAIT*20` 约 10 秒后进入 **`HOVERING`**。右侧队列显示 `20/20`，水平命令 N/E 都为 `0.00`，飞机应保持悬停；继续观察，不要立即点降落。
10. 完成零速度悬停及接管验证后，再重新设置短移动队列开展下一次试验。

“保持同高度”通过竖直速度命令为 0 实现，飞控实际高度可能有波动。偏离本次启动高度超过 0.5 m 时会终止，不会自动修正高度来继续实验。

## 10. 第一次测试真实水平移动

只有前面的悬停与紧急接管验证通过后才进行。

1. 点击“结束控制 / 交还遥控器”，确认遥控器可以操纵。
2. 使用“向北 1 秒 → 悬停 4 秒”预设，速度保持 `0.1`，保存。普通操作无需输入角度；手动导入时仍需注意 **180 表示向北修正，不是朝南飞**。
3. 人工重新飞到适合测试的位置并稳定悬停，重复第 9 节的启动步骤。
4. 理想过程：向北移动 1 秒，随后零速度 4 秒，队列结束后仍持续悬停。理想位移仅约 0.1 m，实际效果要靠观察和记录判断。
5. 如方向错误、位移明显异常、出现高度变化或漂移扩大，立即紧急制动并用遥控器接管，不要继续试其他长队列。
6. 验证北/南/东/西及不同机头朝向时，每次只用短序列，逐次人工重新定位。确认轴映射后再增加队列长度，仍遵守最大速度、时长与预计路程限制。

输入对应表：`0→南`、`90→西`、`180→北`、`270→东`、`WAIT→零速度`。全部约定见 [方向输入说明](direction-input.md)。

**队列执行后的终点可能已偏离最初目标。** App 不会自动返回目标。需要重新对准时，先交还遥控器，再手动调位和降落。

## 11. 序列结束后，人工决定降落

此时可以一直观察悬停、交还遥控器人工降落，或由 App 请求 DJI 自动降落。

- **继续悬停**：不点击降落，程序持续发送零速度；仍受定位、电量、高度、遥测等保护约束。务必留意剩余电量。
- **自己操纵/降落**：点“结束控制 / 交还遥控器”，确认接管后使用遥控器正常操作。
- **让 App 发起降落**：队列结束并稳定悬停至少 2 秒后，点击“人工申请降落…”，目视确认当前正下方适合降落，再点击弹窗“确认”。取消弹窗则继续悬停。

App 会先发零速度并等释放虚拟摇杆成功，再申请 DJI 自动降落。状态 `LANDING_REQUESTED` 表示申请中；`LANDING` 表示 SDK 接受了请求，不表示已经落地。

如果飞控要求再次确认，“DJI 要求最终降落确认…”按钮会启用。先观察原因和落区情况，再决定是否继续。程序不会自动确认或发送强制停机命令。

`COMPLETE` 要求遥测同时报告非飞行且电机停止。仍需目视确认飞机落地、桨叶停止，再靠近。DJI 自身低电量/失联等保护行为仍可能自动发生，“人工决定降落”只约束本程序的正常流程。

## 12. 紧急制动和异常接管

**顶部红色按钮无需二次确认。** 启动/降落确认弹窗中也有“紧急制动”按钮。

按下后的软件动作：立即使本次会话失效 → 停止播放 → 发零水平/竖直速度和零偏航角速度 → 取消本次程序发起的降落（如有） → 在短暂零速度阶段后释放控制权。不会恢复剩余队列，也不会切断电机。

这个按钮是软件制动请求，不是物理急停开关。惯性、通信延迟、飞控、定位和 SDK 状态都会影响实际制动；看见“已请求”不能当成“飞机已停止”。停止或释放失败时，界面明确提示接管，并禁止再次启动。

若手机卡住、断线、按钮无反应或飞机行为异常，**立即使用遥控器**。DJI Mini 4 Pro 官方手册说明，短按飞行暂停/返航键可请求制动悬停，但依赖可用 GNSS 或视觉定位；不要将长按返航误当成短按暂停。应提前在受控条件下验证你所用遥控器、固件和 SDK 模式下的实际接管效果。参见 [DJI Mini 4 Pro 官方手册](https://dl.djicdn.com/downloads/DJI_Mini_4_Pro/DJI_Mini_4_Pro_User_Manual_EN.pdf)。

“交接尚未确认”时不要反复点启动。先确认飞机和遥控器状态；有连接且前一次 SDK 请求已返回失败时，可再次按紧急制动重试取消/释放。没有回调的请求仍会保持锁定。完成手动落地后再排查连接和日志。

## 13. 摄像头遮挡的边界

建议先在完全不遮挡的情况下完成所有控制链路和接管验证。应用本身不读取主相机帧，所以不用遮挡也能检查代码不依赖图像。

如果后续实验必须遮挡，只能遮挡拍摄用的主相机镜头，不能覆盖下视、避障、红外/测距传感器，也不能妨碍云台。无 GPS 时飞控可能依赖下视视觉定位；把这些传感器也蒙住，无法保证定点悬停，程序也应拒绝接管。Mini 4 Pro 的虚拟摇杆避障支持不能作为本实验的防撞保障，仍需空旷的受控空间。

## 14. 如何判定一次实验成功

| 测试 | 软件上应看到 | 现场必须看到 |
| --- | --- | --- |
| 打开 App、保存队列 | 未启动；实机开关关闭或仅显示遥测 | 没有自动起飞/移动 |
| WAIT 队列 | RUNNING，命令 N/E 为零 | 稳定悬停 |
| 短移动队列 | 只有设定时段有非零水平命令 | 方向符合约定、位移与高度变化可控 |
| 队列结束 | HOVERING；命令回零；不出现自动降落请求 | 停止水平移动并继续悬停 |
| 取消降落确认 | 仍 HOVERING | 无主动下降 |
| 紧急制动 | ABORTED、队列停止；交接状态明确 | 飞机受控、遥控器接管有效，无自动续播 |
| 人工批准降落 | LANDING_REQUESTED → LANDING → COMPLETE | 在人工选定落区落地、桨叶停止 |

不能只凭 App 状态判断实际飞行成功，也不能把指令路程积分当成实测距离。一次通过不代表所有机头、环境或固件都通过。

每次实验生成 CSV，右侧显示完整路径。当前本机旧包名的路径通常是：

```text
/sdcard/Android/data/com.zheng13.gradproject/files/experiments/
```

可用 Android Studio 的 Device Explorer 导出，或在手机重新连接电脑并授权 USB 调试后执行：

```bash
/Users/zheng13/Library/Android/sdk/platform-tools/adb pull /sdcard/Android/data/com.zheng13.gradproject/files/experiments ./experiments
```

如果改用新包名，把路径中的 `com.zheng13.gradproject` 改成 `com.zheng13.acousticslanding`。以手机显示的实际路径为准。CSV 记录模式、队列、状态、输入、指令速度、遥测速度、高度、电量、定位状态等；实机没有绝对位置轨迹。按急停会记录 `stop_requested`，这个记录不是硬件已制动的确认。

## 15. 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 sample 模块 | 确认打开的是 `android-sdk-v5-as/`，等待 Gradle Sync 成功 |
| `SDK location not found` | 检查 Android SDK 安装与本机 `local.properties` |
| Java/Gradle 版本报错 | Gradle JDK 选 17，使用项目的 `./gradlew` |
| 下载依赖失败 | 检查网络/代理，关闭 Gradle Offline 模式，重试 Sync |
| 手机不在设备列表 | 解锁并允许 USB 调试，换数据线；Windows 检查厂商驱动 |
| APK 无法覆盖安装 | 同包名签名不一致时按第 6 节处理，先备份 |
| SDK 注册失败/INVALID_METADATA | 核对 Key 和实际包名、手机联网；见 Key 指南 |
| 地面上不能启动 | 正常保护；程序要求先手动起飞和稳定悬停 |
| “没有可用定位”或模式不允许 | 检查下视定位条件、遮挡、光线/地面及飞行模式；不要删除保护 |
| 遥控器能飞但 App 等待遥测 | 先在地面检查六项通信状态；见 [专项指南](connection-troubleshooting.md)，复制逐项读取错误 |
| 数值有显示但报遥测过期 | 看各字段更新时间与硬件读取错误；旧数值不代表链路仍有效，不能盲目放宽阈值 |
| “预计路程超过 3 米” | 缩短数字角度项数或降低速度；WAIT 不计移动路程 |
| 降落按钮不可用 | 需要队列结束且实测稳定悬停 2 秒；紧急停止后的实验不能继续降落流程 |
| 页面返回后不继续 | 正常保护；上次会话已经终止，需重新人工确认并启动 |
